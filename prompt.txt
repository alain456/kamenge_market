Prompt de génération — Frontend web d’administration
Système de gestion du marché / centre commercial de Kamenge
Rôle
Tu es un lead frontend engineer et product designer senior. Construis uniquement le frontend web responsive du back-office d’administration du système de gestion du marché / centre commercial de Kamenge, au Burundi.

Le résultat doit être une interface professionnelle, réellement navigable et prête à être branchée à une API plus tard. Ne construis pas l’application mobile des commerçants/clients : cette application sera développée séparément. Le périmètre ici concerne exclusivement les utilisateurs internes du marché : administrateur, agent du marché, comptable/agent de saisie, chef comptable/responsable financier et direction générale.

Stack et contraintes techniques
React avec TypeScript.
Vite.
Tailwind CSS.
React Router pour la navigation.
Utiliser des composants réutilisables et une architecture par fonctionnalités.
Utiliser Lucide React pour les icônes.
Utiliser Recharts pour les graphiques si nécessaire.
Utiliser des données mockées locales réalistes, en français, afin que toutes les pages soient démontrables sans backend.
Préparer une couche services/ ou api/ avec des fonctions asynchrones simulées, afin de remplacer facilement les mocks par de vraies requêtes HTTP.
Ne pas écrire de backend, de serveur, de migration, de base de données, de logique Laravel ou de système d’authentification réel.
Ne pas appeler de vraie API et ne pas demander de clé secrète.
Prévoir les états loading, empty, error et success dans les composants.
Le code doit être propre, fortement typé, maintenable et organisé.
Objectif produit
Créer le tableau de bord central de gestion du Mall Kamenge. L’administrateur doit pouvoir comprendre l’état du marché en quelques secondes, repérer les impayés, vérifier les bordereaux, gérer les commerçants et les emplacements, suivre les contrats et produire des rapports.

L’interface doit donner une impression de contrôle, de traçabilité et de sécurité financière. Elle doit être adaptée à un usage quotidien par une équipe administrative, avec beaucoup de tableaux, de filtres, de statuts et d’actions de validation.

Direction artistique
Créer une interface SaaS administrative moderne, sobre et crédible, inspirée des outils de gestion financière et immobilière.

Langue de l’interface : français.
Devise principale : BIF / Franc burundais.
Format des montants : lisible, avec séparateurs de milliers et suffixe BIF.
Format des dates : français, par exemple 26 août 2026.
Palette principale :
bleu nuit / bleu ardoise pour la navigation et les titres ;
bleu vif comme couleur d’action principale ;
vert pour les emplacements libres et les paiements à jour ;
jaune pour les bordereaux en attente ;
rouge pour les impayés, retards et rejets ;
noir ou gris anthracite avec motif/hachures pour les emplacements scellés.
Fond général gris très clair, cartes blanches, bordures fines, ombres discrètes.
Typographie sans-serif très lisible.
Contraste accessible et états ne reposant pas uniquement sur la couleur : ajouter texte, icône ou badge.
Interface dense mais respirante : les tableaux doivent être efficaces sans devenir visuellement étouffants.
Prévoir un mode sombre seulement si cela ne complexifie pas inutilement le MVP ; la priorité est le thème clair.

Critères d’acceptation
Le frontend est considéré comme réussi si :

L’application démarre avec une commande Vite standard et ne présente aucune erreur console bloquante.
La page de connexion mène vers un dashboard fonctionnel avec un utilisateur mocké.
Toutes les routes principales sont accessibles depuis la sidebar.
Les pages clés contiennent des données réalistes et cohérentes.
Les filtres, recherches, onglets, drawers, modales et actions principales fonctionnent côté frontend.
Le workflow de validation des bordereaux impose un motif lors d’un rejet.
Le workflow comptable empêche de valider une pièce déséquilibrée.
Le workflow de décaissement respecte les états et les permissions.
La vue des emplacements utilise les cinq codes couleur/statuts demandés.
Les dossiers d’impayés sont triés par montant d’arriérés décroissant par défaut.
Le détail d’un dossier affiche l’historique des relances.
L’attribution bloque un emplacement non libre et calcule la caution.
Les actions réservées à certains rôles sont masquées ou désactivées proprement.
Le design est responsive, accessible et entièrement en français.
Le code ne contient pas de backend ou de secrets et peut être branché à une API ultérieurement.
